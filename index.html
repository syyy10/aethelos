Aethel Linux

Your PC Your choice · Early development · Alpha demo

Aethel Linux is a minimal, systemd-free Linux distribution built around user control. It pairs a small runit-based system with its own package manager (APM) and a command-line system management tool (ASMT).

[001] Overview

Aethel Linux is a minimal Linux distribution for people who want to decide what is installed and running on their computer. Instead of handing you a finished desktop, it hands you a small foundation and lets you build upward from there.

The philosophy

Your system should contain the tools and services you choose, and nothing else. Many distributions ship with a preinstalled desktop environment, default applications, and background services most people never asked for. Aethel Linux skips all of that, so there is nothing to strip out before you can start making the system your own.

Who it is for

  • People who want to understand what is running on their machine and why.
  • People who enjoy assembling their own environment: picking a window manager, adding applications one at a time, and deciding which services start at boot.
  • People who prefer the command line and want tools that stay small and readable.

Where it stands today

Aethel Linux is in early development. Expect bugs, unfinished features, and limited hardware support. The current release is best thought of as an alpha demo: a working look at the direction of the project, not a finished daily-driver system.

[002] A Small Base, Your Choices

Aethel Linux uses runit and is systemd-free. Around that base sit two project-specific tools: APM, the package manager, and ASMT, the command-line system management tool.

Why runit

runit is a lightweight init system and service supervisor. Each service is described by a small directory containing a script that starts it, and runit keeps those services running and restarts them if they stop. Because the pieces are simple, it is easy to read how your system boots and what it is supervising, which fits the goal of a system you can fully understand.

What systemd-free means

Aethel Linux does not use systemd as its init system or service manager. Services are handled by runit instead, which keeps the init layer small and avoids tying the rest of the system to a large, all-in-one framework.

The three parts of the system

PartRole
Minimal baseA small starting system with no preinstalled desktop or extra applications
APMInstalls, removes, updates, and describes packages
ASMTCommand-line management for administration tasks (in development)

The goal

A system that stays understandable as you make it your own. Add the applications you need, choose the services you run, and keep the rest out of the way.

[003] APM — Aethel Package Manager

APM is a small package manager written in C. Its current codebase is roughly 800 to 1,000 lines, and it depends only on basic system utilities. Keeping it this compact is deliberate: the whole tool is small enough for a user to read and follow.

How packages are installed

  1. Look up the package archive in index.txt.
  2. Download the tar.gz package.
  3. Extract the archive.
  4. Install its files onto the system.

Current commands

add       Install a package
remove    Remove a package
update    Update packages
info      Show package information
CommandWhat it does
addInstalls a package from the index
removeRemoves an installed package
updateUpdates installed packages
infoShows information about a package

Status

APM is still being developed. Expanding and refining its command set is one of the next priorities. Because package repositories have so far only been tested locally (see [005]), APM is currently aimed at development and testing rather than everyday use.

[004] ASMT — Aethel System Management Tool

ASMT is a command-line system management tool being developed for Aethel Linux. It is inspired by the role YaST plays in openSUSE: a single, central place for common administration tasks rather than a scattering of separate utilities. In ASMT's case, everything is meant to be done from the terminal.

Intended scope

AreaGoal
System rollbacksReturn the system to an earlier state if a change goes wrong
Service managementEnable, disable, and control the services you choose to run
Disk partitioningPrepare and manage disks without hunting for separate tools
Package installation and discoveryMake it easier to find and install software

The aim

Make common administration tasks more convenient from the terminal while keeping the system small and understandable, in line with the rest of the project.

Status

ASMT is part of an early development effort. Feature availability and behavior are still being established, so details may change as the design settles. Supporting additional init systems in the future would also require corresponding changes to ASMT (see [006]).

[005] Repositories & Hardware

Package repositories

Package repositories have only been tested locally so far, and public repositories are not available yet. Building and hosting them is a priority as development progresses. Until then, packages for APM come from local testing setups rather than a public server.

Hardware support

Hardware support is currently limited. Testing has focused on virtual machines, specifically QEMU and VirtualBox. Broader hardware support will require more development and testing.

Trying it today

EnvironmentStatus
QEMUTested
VirtualBoxTested
Other virtual machinesNot yet a focus
Physical hardwareLimited; needs more development and testing
Public package repositoriesNot yet available

If you want to explore Aethel Linux in its current state, a virtual machine is the safest and best-supported way to do it.

[006] What Comes Next

Near-term priorities

  • Refine APM and expand its command set.
  • Build and host public package repositories, so packages are available beyond local testing.
  • Improve the base system and test on more hardware.

Longer-term ideas

Raspberry Pi and 32-bit editions. These would require architecture-specific packages, repositories, and compatibility work across the system.

Additional init options. These are being considered alongside runit:

  • Finit
  • BusyBox Init
  • S6
  • 66
  • Sysvinit
  • OpenRC
  • dinit

Supporting any of them would require corresponding changes to ASMT, since service management is part of its intended scope.

A note on expectations

These are future possibilities, not release commitments. Aethel Linux remains an early-stage project.
